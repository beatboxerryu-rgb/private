# M365案件のvault連携

このノートは 50_laws に置く。M365 関連のスキル（要件定義・設計・テスト設計・
影響調査・現行調査・技術調査）が発動したときに、あわせて参照する。

スキルの手順や観点はここに書かない。重複させると二重管理になるため。
ここに書くのは vault との接続だけ。

---

## 発動条件

M365 関連のスキルが発動したとき。ただし単発の調べ物で判断が生まれない場合は
書き込み不要。

---

## ID を vault の検索キーにする

各スキルが採番する ID を、ノートの topic プロパティではなく本文の見出しに残す。

| スキル | ID | vault に残すもの |
|---|---|---|
| 現行調査 | GAP-001… | ギャップの判断根拠、収集手段の選定理由 |
| 要件定義 | FR-001 / NFR-… | 要件化した理由、却下した要件案 |
| 設計 | DS-001… | Decision Log（採用案・不採用案・理由・トレードオフ） |
| テスト設計 | TC-001… | 網羅できなかった観点とその判断 |
| 影響調査 | RAID項目 | 重大度の判定根拠 |
| 技術調査 | なし | 比較の評価軸と、選定理由 |

ID は案件をまたいで再利用されるため、ノートには必ず案件を特定できない形で
一般化して書く。「A社の FR-012」ではなく「〇〇な制約下での FR 相当の判断」。

---

## 書き込みの基準

書く

- 選択肢を比較して1つを選んだとき（不採用案とその理由が本体）
- 一次情報を確認して、事前の想定と違ったとき
- Open Question / 未確認事項として残したまま先に進んだとき
- 顧客固有の制約が判断を変えたとき（制約は一般化して書く）

書かない

- Microsoft Learn を引けば済む仕様や上限値
- 成果物そのもの（Word / Excel は vault に入れない）
- 案件固有の設定値、テナント識別子、社名

---

## 成果物と vault の分担

スキルの成果物は Word / Excel で、これは vault に置かない。
vault に置くのは、その成果物を作る過程で下した判断だけ。

成果物 = 何を作ったか
vault = なぜそれを選んだか

---

## 出典の扱い

スキル側で既に「出典 URL と参照日を付す」が義務づけられている。
vault のノートでも同じ形式を守る。憲法5条と一致するため、追加の規約は不要。

---

## Decision Log との関係

設計スキルは Decision Log を残すよう求めているが、置き場を指定していない。
ここでは vault の 10_notes を永続的な置き場とする。

設計書内の Decision Log は当該案件のもの。
vault のノートは案件をまたいで参照する一般化された判断。
両方書く。粒度が違う。
