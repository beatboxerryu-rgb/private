# M365 E5導入プロジェクトまとめ

Office 365 E1 利用中の顧客向けに、Microsoft 365 E5 のセキュリティ機能を説明する資料(5ファイル・計87スライド)を作成し、3回のレビューを経て品質を確保したプロジェクトの記録。要件定義フェーズの手前に位置づけられる。

## 対象資料の構成

| 分冊 | 内容 |
| --- | --- |
| 機能マップ編(全体像) | E5 とは/E1 比較/保護範囲図/攻撃の流れ/製品間連携図/用語集 |
| Entra ID 編 | MFA/条件付きアクセス/ID 保護/PIM/Windows Hello for Business |
| Defender 編 | Defender XDR/MDO/MDE/MDCA/MDI/MDVM |
| Purview・Priva 編 | 秘密度ラベル/DLP/監査/eDiscovery/Priva(アドオン・参考) |
| Intune 編 | 端末管理/EPM ほか Intune Suite 由来機能 |

各冊とも「〜とは → 目的 → ユーザー目線 → シナリオ → 仕組み → 連携」の6段構成で統一。メインメッセージは「E5 は、いまの M365 に『気づく・止める・説明する』をまとめて加える」。

## 主要な指摘と反映内容

### 正確性(ライセンス関連の誤り修正)

- Priva は E5 包含ではなく別途アドオン。全体像デッキの3か所を修正し統一。さらに Priva は再編中(2025年12月にプレビュー機能廃止、SRR は Purview eDiscovery Premium ベースへ移行進行中)のため「提案時は最新情報を確認」の注記を追加
- Teams 非バンドル: 2024年4月以降の新規契約では Teams は別売(no Teams SKU が原則)。注記を追加
- EPM(エンドポイント特権管理)ほか Intune Suite 由来機能(Cloud PKI、Enterprise App Management 等)は 2026年7月1日のパッケージ変更で E5 に順次追加。「Intune Plan 2/Suite を包含」という不正確な表現を機能名ベースに修正
- Security Copilot: 2026年7月から E5 に利用枠(SCU)が追加。「E5 とは」に追記
- MDVM はコア機能が E5、フル機能は別アドオン。注記を追加
- 攻撃シミュレーション訓練は MDO Plan 2 の機能で E5 に含まれる(追加費用と誤読されない表現に修正)
- Azure AD B2C は新規販売終了(2025年5月)のため「外部 ID(External ID)」に表記更新
- MFA は E1 でも利用可能。E5(P2)が加えるのはリスク連動の自動判定である旨を注記
- 「E1 は端末管理の仕組みはない」→ Basic Mobility and Security を考慮し「Intune のような本格的な端末管理はない」に修正

### 整合性・体裁

- ページ参照を分冊名参照(別冊:◯◯編)に統一
- 用語集を巻末へ移動し記載と一致させた
- 攻撃の流れ図の検知主体を「MDCA + Entra が検知」に統一
- 括弧の全角/半角、「別料金」「1 か所」「SRR」等の表記ゆれを統一

### 論理構成(フレームワーク再レビューでの反映)

- 構成の一方向化: 「E5 とは/E1 比較」を前半へ移動し、抽象→具体の流れに整理
- 巻末に「次のステップ」1枚を追加(要件定義への橋渡し)
- 想定読者の明記(情シス部門/意思決定者の読み方ガイド)
- 脅威統計の出典追記: Microsoft Digital Defense Report 2025 を引用(フィッシング耐性の MFA は ID 攻撃の 99% 以上を防ぐ)
- スコープ外宣言: ネットワーク保護(Global Secure Access 等)・Azure 基盤保護(Defender for Cloud)は別ライセンスのため対象外と明記
- 「費用・スケジュールは要件定義で扱う」の宣言を追加
- 各サービス編4冊の巻末に「要件定義で決めること ― 5つの論点」を追加
  - Entra: 認証方式/条件付きアクセス方針/リスク強度/PIM 運用/展開順
  - Defender: 導入範囲/端末展開/自動対応レベル/検疫・例外運用/監視体制
  - Purview・Priva: ラベル体系/保護優先順位/DLP 段階/例外運用/Priva の扱い
  - Intune: 登録方式/準拠基準/私物端末/救済手順/EPM 運用

## 資料の強み(評価済み)

- 全製品で一貫した6段構成の小ピラミッド(資料最大の強み)
- 「ひとことで言うと」「たとえるなら」「E1 との違い」の三点セット
- E1/E5 比較の「事実 → 解釈 → 打ち手」(空・雨・傘)の分離が高水準
- ユーザー目線ページ(利用者が意識しなくてよいこと/残る判断)が秀逸
- レイアウト・配色・アイコン使いは統一感があり破綻なし

## 要件定義フェーズへの引き継ぎ事項

- 顧客の実契約 SKU の確認を冒頭で行う(Office 365 E1 か、Teams 付きか no Teams か)
- Priva を提案範囲に含めるか、E5 包含の eDiscovery(Premium)で代替するかの再検討
- 2026/7/1 パッケージ変更(EPM 等)は段階展開のため、提案確定前にライセンスガイド/メッセージセンターで最終確認
- 「動いている前提」(Priva 再編・パッケージ変更)を含むため、提案が数か月先になる場合は記載の再確認が必須
- 保護範囲図・攻撃の流れ図は機能マップ編と Defender 編に重複掲載。二重管理のマスターをどちらにするか運用ルールを決める
