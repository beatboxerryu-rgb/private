# 結論
複数案件を vault で分離しない。フォルダは案件別にせず、
00_inbox のプロパティ case で一時的にラベルし、昇格時に外す。

# 昇格条件
2案件を並行して1ヶ月運用し、案件をまたいだ参照が実際に起きたら verified。

# 理由
判断: vault の目的は案件をまたいで再利用できる判断の蓄積。
      案件ごとにフォルダを切ると、その参照が起きにくくなる
判断: 憲法1条により社名が書けないため、フォルダ名は匿名ラベルになる。
      半年後に何のことか分からなくなる可能性が高い

# 採用する運用
00_inbox : frontmatter に case: A / B / C を持たせる。匿名ラベル。
           Bases のフィルタで稼働中の案件だけを絞り込める
10_notes : 昇格時に案件依存の記述を一般化し、case を削除する

判断: 昇格とは案件から切り離す作業でもある。
      00_inbox は案件別、10_notes は案件横断。これがフォルダの意味になる

# 対応表の扱い
判断: どのラベルがどの顧客かの対応表は vault に置かない。
      憲法1条に抵触するため、ユーザーの手元で管理する

# Claude 側のプロジェクト
判断: 案件ごとにプロジェクトを作らない。憲法を複数箇所にコピーすることになり、
      改正時に食い違う。実務プロジェクトは1つのまま、案件はチャット単位で分ける

# 反証
案件数が5件を超えると、case ラベルだけでは追えなくなる可能性がある。
その場合はフォルダ分割を再検討する。

# 未検証

promote_if、proposal に続く。増やしすぎの兆候かもしれない。
