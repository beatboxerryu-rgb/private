# 計画・レビューに適用する思考法・フレームワーク集

> [!info] 位置づけ
> 本プロジェクト (ADリプレース / GPO→Intune 移行) の計画立案・レビュー・資料作成時に適用する観点集。
> 第1部 = 19思考法 (思考のOS)、第2部 = ビジネスフレームワーク36種 (思考の道具箱)。
> レビュー依頼時は末尾の「5問チェック」を必ず通す。
> 索引: [[ADリプレース 索引]]

## 第1部 思考法一覧 (19種)

- 論理系: ロジカルシンキング (MECE・ロジックツリー・ピラミッド) / クリティカルシンキング (前提を疑う) / 演繹的思考 / 帰納的思考 / アブダクション (最尤仮説)
- 創造系: ラテラルシンキング / デザイン思考 (共感起点) / アート思考 (内発的問い) / アナロジー思考 / ブレインストーミング的発散
- 前提転換系: ゼロベース思考 / 仮説思考 (仮説→検証) / バックキャスティング (未来から逆算) / メタ思考 (思考の俯瞰) / システム思考 (因果ループ・全体構造)
- 実践応用系: 戦略的思考 (選択と集中) / リフレーミング / 逆説思考 / 弁証法的思考 (テーゼ・アンチテーゼ→ジンテーゼ)

## 第2部 ビジネスフレームワーク36種 (10カテゴリ)

- 環境分析: PEST分析 / ファイブフォース分析 / 3C分析 / SWOT分析 / クロスSWOT分析 / VRIO分析
- 戦略立案: STP分析 / アンゾフの成長マトリクス / PPM (BCGマトリクス) / バリューチェーン分析 / ビジネスモデルキャンバス
- マーケティング: 4P / 4C分析、カスタマージャーニーマップ、AIDMA / AISAS、AARRR (海賊指標)
- 思考整理・問題解決: ロジックツリー / ピラミッドストラクチャー / MECE / ペイオフマトリクス / デザイン思考プロセス
- プロセス・改善: PDCAサイクル / OODAループ / DMAIC / ECRS (改善の4原則) / As-Is・To-Be分析 / KPT
- 情報整理: 5W1H / 空・雨・傘
- カテゴライズ: KJ法 (親和図法) / 帰納法 (共通項の抽出)
- 比較: ポジショニングマップ / Pros・Cons比較
- 検討: ディシジョンツリー / 6つの帽子 (シックスハット法)
- 評価: 意思決定マトリクス (重み付け評価) / RICEスコア

## 19思考法との対応 (主なもの)

- ロジカル系思考の実装ツール = ロジックツリー、ピラミッドストラクチャー、MECE、5W1H
- 仮説思考・帰納 = 帰納法 (共通項の抽出)、空・雨・傘 (事実→解釈→行動)
- バックキャスティング = As-Is / To-Be 分析 (To-Be 起点でギャップを課題化)
- デザイン思考 = デザイン思考プロセス (5段階)、カスタマージャーニーマップ
- クリティカル・多角的検討 = 6つの帽子、Pros/Cons 比較
- 戦略的思考 (選択と集中) = ペイオフマトリクス、意思決定マトリクス、RICEスコア、クロスSWOT
- システム思考 = ディシジョンツリー (分岐構造化)、AARRR (ボトルネック特定)
- ブレスト発散の収束 = KJ法 (親和図法)

## 本プロジェクトでの使いどころマップ

### 判断・意思決定 (OP-xx 判断、方式選定)

- Pros/Cons 比較 → OP 判断事項の提案時の標準フォーマット (致命的 Cons の有無を明記)
- 意思決定マトリクス → E 代替検討で代替手段が複数ある設定の移管先選定 (重みを先に合意)
- ディシジョンツリー → D-1 サーバー計画 (残存寿命×方式) の分岐図示、A 廃止判定フローの説明
- 6つの帽子 → E-1 (利便性設定の廃止受容) など対立が予想される業務側合意の会議設計

### 優先順位付け (波計画・バックログ)

- ペイオフマトリクス → A 廃止・C 移管の波割り当て (効果 = 設定数/リスク、実現性 = 依存の少なさ)
- RICE スコア → C 移管プロファイル作成順の機械的な優先度付け (Reach = 適用台数、Confidence = 分類確度)

### 改善・運用ループ

- ECRS → A 廃止判定の思想そのもの (E 排除が最優先 = まず廃止を検討、現状の GPO をそのまま移さない)
- KPT → 波ごとのふりかえりの標準形式 (Try は担当と期限まで)
- PDCA / OODA 使い分け → 波の計画的実行 = PDCA、パイロットでの想定外対応 = OODA
- DMAIC → 分類ルール育成サイクルの説明 (測定 = 棚卸しCSV、分析 = 誤分類、改善 = ルール追記、定着 = v1.0化)

### 現状分析・報告

- As-Is / To-Be → 計画書の構造の背骨 (As-Is = AD/GPO 300本、To-Be = クラウドオンリー、ギャップ = 5出口)。OP-08 (廃止目標日) が決まれば To-Be 起点の逆算が完成
- 空・雨・傘 → 進捗報告・エスカレーションの標準話法 (事実 = KPI 実測、解釈 = ボトルネック、行動 = 依頼)
- 5W1H → 調査依頼票 S-01〜S-13 の記入項目設計、告知文のチェック
- KJ法 → S-04 (GPO 棚卸しヒアリング) の自由記述整理、E 設定の業務側意見の構造化

### 利用者コミュニケーション (デザイン思考系)

- カスタマージャーニーマップ → 利用者影響・コミュニケーション計画 (提案中) の中核手法。移行の波を利用者視点の時系列 (予告→切替日→直後→定着) で描き、感情が下がる場面に告知・救済を置く

### 適用しない / 慎重にするもの (過剰適用の防止)

- PEST / 5F / 3C / SWOT / STP / 4P / PPM / BMC / AIDMA / AARRR 等の事業戦略・マーケ系は主対象外。ただし SWOT / クロスSWOT は経営層向け1枚説明 (なぜ今移行するか) に限定的に有効
- フレームワークは「意思決定に効くか」で選ぶ。埋めること自体が目的化したら精緻化バイアスの兆候

## 適用で得た気づき (2026-07-29 適用結果)

- バックキャスティング欠如: 計画はフォアキャスト型で「AD 廃止予定日」が未定義。B/D/凍結期間の妥当性は廃止日からの逆算でしか検証できない → OP-08 (AD 廃止目標日の設定と逆算線表) を提案
- デザイン思考欠如: 全成果物が管理者視点。利用者の体験変化 (ドライブ消失・プリンター変更・設定廃止) の影響一覧と告知計画が未整備 → 成果物候補に追加提案
- システム思考: 「凍結長期化→例外申請増→凍結形骸化→棚卸し陳腐化」の強化ループリスク。対策 = 波を小さく速く回し凍結期間を最短化
- 弁証法: 現計画は「速度優先の一括移行」と「安全優先の段階移行」のジンテーゼとして説明可能。E-1 反対意見には「一括承認＋異議申立窓口」がジンテーゼ
- 逆説思考の極論テスト: 「300本全部廃止できないか？」を Phase 1 の問いに含める (集約20〜40本の根拠を強化)
- メタ思考: このプロジェクトの既知バイアス = 精緻化バイアス (文書作成が進捗に見え、実測が先送りされる)。レビュー毎に「実測を先送りしていないか」を確認

## レビュー時の5問チェック

1. ゼロベース: そもそもこの作業・成果物は目的 (クライアント適用 GPO 0本) に必要か
2. クリティカル: この判定・数値の根拠は実測か仮置きか。仮置きに精緻さの錯覚はないか
3. バックキャスト: AD 廃止日から逆算して間に合うか。最遅開始日はいつか
4. システム: このルール・ツールが生む副作用ループ (形骸化・回避行動) はないか
5. デザイン: 利用者はこの変更をどう体験するか。告知・救済は用意されているか

## 資料作成時の型

- 提案スライドは 空・雨・傘 (事実→解釈→提案) の3段構成を基本にする
- 判断依頼は Pros/Cons (重み付き、致命的 Cons 明記) で提示する
- ふりかえりは KPT、優先順位はペイオフマトリクス (4象限) を第一候補にする
- 図解集の各スライドのレイアウト (概要 / 使いどころ / ワンポイント＋図) は説明資料の参考テンプレートとして流用可
