# 結論
Filesystem コネクターの許可ディレクトリ限定は、ファイル内容と
ファイル名の遮断としては有効。ただしディレクトリ名の存在は
別経路（Cowork のデバイスブリッジ）から見えるため、秘匿はできない。

# 昇格条件
Cowork のデバイスブリッジ経路の権限設定を確認し、制御可否が判明したら verified。

# 確認された事実
事実: 2026-08-13、許可ディレクトリを 00_inbox のみに設定した状態で、
      vault 直下のディレクトリ名一覧（10_notes、50_laws、90_archive、
      .git、.obsidian）が別経路から取得できた
事実: 同時に、ファイル名およびファイル内容は取得できなかった。
      接続済みフォルダは 00_inbox のみ
      （出典: 本セットアップ作業での実機確認。第三者ソースなし）

# 評価
判断: 保護目的（Claude が 10_notes の verified を書き換えない）は
      達成されている。内容が読めず書き込めないため
判断: ただし「遮断」ではなく「部分遮断」。存在の秘匿はできない
判断: 機密を vault に入れない方針（憲法1条）があるため、
      今回の構成では実害は小さい。方針が変われば問題になる

# 設計への反映
判断: 「事前防止に変わった」という評価を撤回し「部分遮断」に修正
判断: Git は保険ではなく、引き続き必要な検知層として維持する
判断: 段階3への早期移行は、前提が弱まったため再検討が必要

# Claude の誤り
判断: 8/7 の確認で「00_inbox が見えるか」のみを検証し、
      「10_notes が見えないか」を検証しないまま遮断成立と結論づけた。
      肯定側の確認だけで結論を出す推論の誤り
