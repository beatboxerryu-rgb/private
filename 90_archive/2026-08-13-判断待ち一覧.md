# 判断待ち

1. 憲法第9条を採用するか
   Claude が自分の誤りを記録するノートに限り、承認なしで書けるようにする条項。
   Claude 自身が提案した、Claude に有利な権限。初日の実績では誤り5件のうち
   Claude が自力で気づいたものは0件だったため、効果は限定的と Claude は見ている。

2. フィットネス関数 F1 の扱い
   author=claude かつ status=verified を0件に保つ検査は、設計に欠陥がある。
   昇格済みノートは必ずこの条件に該当するため、全件を違反として拾う。
   修正案は Git の差分で検査する方式（M3 以降でないと実行不可）。
   M2 期間中は憲法2条を機械的に検査する手段がない状態になる。

3. 撤退ラインの分母を変えるか
   現行は「4週目に verified 5件以上」。ただし今 vault にあるのは全て
   vault 自身についてのノートで、昇格しても仕組みが役立つ証拠にならない。
   「実務案件から生まれた verified が2件以上」への変更を提案。

4. 初回のみ複数昇格するか
   16件を週1件で消化すると16週かかる。今日のノートは同時に生まれた足場のため、
   初回はまとめて仕分け、その後に週1件のリズムへ入ることを提案。

5. proposal プロパティを廃止するか
   Claude が本日追加したが、ファイル名を「提案-」で始めれば同じことができる。
   プロパティを増やさない原則への違反を撤回する提案。

6. related を昇格時に [[ ]] へ変換するか
   現行は文字列のため Obsidian 上でリンクとして機能せず、バックリンクも
   グラフも効かない。空リンク回避のための意図的な設計だったが、
   実物を見ると飾りになっている。

7. 失敗記録を優先的に昇格させるか
   Claude は 00_inbox に上書き権限を持つため、自分の失敗記録を改変できる。
   10_notes へ移せば Claude の書き込み範囲外になる。

8. スマホ閲覧の要否
   必要なら Obsidian Sync（月4ドル前後）。不要なら課金なし。
