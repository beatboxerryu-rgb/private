# 結論
Filesystem MCP サーバーの許可ディレクトリを 00_inbox のみに絞れば、その MCP を経由した 10_notes へのアクセスは仕様上遮断される。ただし効果はその MCP 経路の内側に限られ、Claude 全体からの遮断ではない。

# 昇格条件
Filesystem MCP 以外の経路を含めて 10_notes に到達できないことを実機で確認できたとき。

# 根拠
事実: Filesystem MCP サーバーは、起動引数または Roots で指定されたディレクトリ内にのみ全ファイル操作を制限する（https://mcpservers.org/servers/modelcontextprotocol/filesystem 、2026-08-13 確認）
事実: クライアントが Roots に対応している場合、クライアント側の Roots が起動引数で指定した許可ディレクトリを完全に置き換える（https://mcpservers.org/servers/modelcontextprotocol/filesystem 、2026-08-13 確認）
事実: 許可ディレクトリ外への到達を許す脆弱性 CVE-2025-53110（プレフィックス一致の不備）と CVE-2025-53109（シンボリックリンク経由）が公開され、2025.7.1 で修正された（https://cymulate.com/blog/cve-2025-53109-53110-escaperoute-anthropic/ 、2026-08-13 確認）
判断: 許可ディレクトリの限定は、法律3（10_notes は読み取り専用）を運用ルールから技術的制約へ格上げする有効な手段である。ただし単一の防御層にすぎず、これをもって「遮断済み」と言い切ると他経路が盲点になる。

# 反証
次のいずれかが成り立てば結論は崩れる。

1. Filesystem MCP 以外の経路が vault に到達する場合。本日のセッションでは、Claude Desktop のフォルダ接続機能が Filesystem MCP の許可ディレクトリ設定とは独立に動作し、vault 直下のディレクトリ名一覧（10_notes、50_laws、90_archive を含む）が取得できたうえ、10_notes への接続要求も出せる状態だった。
2. クライアントが Roots を送出する構成に変わり、起動引数の許可ディレクトリが置き換えられた場合。
3. サーバーが 2025.7.1 未満のまま運用されている場合。
