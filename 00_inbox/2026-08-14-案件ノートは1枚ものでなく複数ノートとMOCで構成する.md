# 結論
案件情報を1枚の総合ノートにせず、複数ノートに分割してトップの MOC から
内部リンクで辿る構成を採用した。

# 昇格条件
この vault の Bases 主体の構成と MOC 主体の構成、どちらを主とするか決まったら verified。

# 根拠
判断: 分割案はタグ、グラフビュー、個別参照を活かせる
判断: 不採用案の1枚総合ノートは取り込みが簡単だが、参照粒度が粗く、
      後から手動分割が必要になる

# 反証
ノート数が増えると更新時に複数ファイルの整合を取る手間が生じる。
元情報が変わった場合の追従は1枚ものより重い。

# この vault の方針との関係
判断: 本 vault は Bases の表を主とし、リンクを補助とする設計で進めてきた。
      一方この判断は MOC とリンクを主とする構成であり、方向が異なる
判断: 同居は可能だが、どちらを主とするかを決めておかないと、
      案件ノートと vault 運用ノートで参照の仕方が二分される
判断: 現時点では Bases が主、リンクは補助という位置づけのまま保留とする

# 未検証
実際の vault 環境での取り込み結果（既存ノートとのタグ・ファイル名衝突の有無）は未確認。
Bases 主体と MOC 主体のどちらが実務で機能するかも未検証。
